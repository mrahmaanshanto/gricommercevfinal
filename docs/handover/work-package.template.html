Module C · SEO controls (store-wide and on every page type)

Why: an SEO manager's checklist for custom websites lists the controls SEO staff need on every editable page. Grid Commerce has some of them in some places (meta title/description on pages, posts, products; canonical only on posts), none on categories or landing pages, and nothing for link nofollow, custom schema, redirects or sitemaps. SEO is also a paid service in Module B, so the tools must be good enough for an expert to work in.

C2 · Automatic schema (so merchants don't have to write JSON)

Product (name, image, brand, SKU/GTIN, offers with price in BDT and availability from live stock, aggregate rating from Reviews), BreadcrumbList, Organization/LocalBusiness (from Settings › General: name, logo, address, phone, map), Article (blog), FAQ (when a page has an FAQ block). Custom schema of the same type replaces the automatic one; never output both.

C3 · Store-wide SEO tools (Settings › SEO, or Online Store › SEO)

  • Redirects: 301/302 list, add/import CSV, auto-create when a page/product/category/post handle changes, loop and chain warnings (review item ON-F19).
  • 404 log: missed addresses with hit counts → one click to create a redirect (demo data).
  • Sitemap: which types are included, excluded noindex items, last updated; view the list.
  • robots.txt: safe default, editable with a warning before blocking the whole site.
  • Bulk SEO editor: a grid (like Bulk edit) for titles, descriptions, handles and image alt across products/categories/pages.
  • SEO health: a score per item and a list of issues across the store (missing description, duplicate titles, too long, missing alt, noindex by mistake, broken internal links), each with "Fix".
Don't build: keyword-rank tracking, backlink tools, AI-written meta for every product by default (offer it per item, reviewed).

Module A · Storefront builder (WoodMart-style, minimal)

Why: merchants judge a store builder by how their shop looks and how quickly they get there. Today Grid Commerce has Pages, Menus, Reviews, a landing-page builder and a super admin theme library, but no theme editor and no customer storefront drawn by a theme. Merchants who know WooCommerce themes like WoodMart expect a header builder, reusable blocks, layouts, a mega menu and one-click demos. WoodMart has 300+ options; most merchants touch 20. We build the core that makes a shop look professional, with strong presets.

How it fits together (one engine)

Preset (demo) → sets Theme settings + a Header + Layouts (made of sections) + HTML blocks + menus and sample pages. Sections and HTML blocks are one shared library, also used by landing pages later. Super admin › Storefront themes decides which presets exist, which plans get them and what merchants may edit (switches already there).

Module B · Services (merchants buy expert help)

Why: merchants need help we can sell: SEO, branding, Meta and Google ads experts, custom store design, product uploading, setup and migration, content. A services shop inside Grid Commerce earns revenue, keeps merchants from leaving for agencies, and makes the product feel complete. Super admin already has a service catalogue and service income (Finance › Income). Store access sessions (built in Phase 1) let an expert work inside a merchant's store safely, with the owner's approval and a time limit.

B1 · Merchant side (menu: Services)

  1. Catalogue: cards by category (Grow sales: SEO, Meta ads, Google ads · Look: branding, custom store design · Setup: product upload, migration, store setup · Content: product descriptions, photography guidance). Each service: what you get, packages (e.g. Starter / Standard / Pro with BDT price, delivery days, revisions, what's included), one-time or monthly (SEO and ads are monthly retainers), FAQs, sample work, rating.
  2. Order: pick package and add-ons → short brief form made for that service (goals, competitors, links, brand files, budget for ads spend — kept separate from our fee) → pay (bKash / Nagad / card or GridCommerce credits; demo) → invoice with VAT as set in admin.
  3. My services: each order shows status (Brief received → In progress → Waiting for you → In review → Delivered → Closed), due date, the expert, a message thread, files and deliverables, "Approve" or "Request a change" (revision count left), rating at the end. Monthly services show this month's report.
  4. Store access: when a service needs to work in the store (product upload, SEO, design), the order asks the owner to approve a store access session with the right scope (e.g. Products only, Online Store only) and duration — uses the Phase 1 access sessions.

B2 · Super admin side (Services area)

  • Catalogue & packages: services, packages, add-ons, prices, delivery days, revision limits, brief form builder per service, which editions/plans see each service, publish/pause.
  • Orders board: new / in progress / waiting for merchant / in review / overdue / delivered; SLA timer that pauses while waiting for the merchant; priority; filters by service and expert.
  • Experts: internal staff and outside partners with skills, capacity, current load, rating, commission %; assign or auto-suggest by load; request store access on the merchant's behalf.
  • Quality check: optional review by a lead before delivery; revision tracking; scope-change requests become a paid add-on quote.
  • Money: income to Finance › Income (exists), partner payouts as liabilities, refunds (full before start, partial after, with reason and approval), monthly retainers billed with the subscription.
  • Reports: orders and revenue by service, on-time %, revisions per order, rating by service and by expert, repeat buyers.
Watch out: scope creep (fixed package scope, paid add-ons for more), merchants who go quiet (pause the SLA, auto-close after N days with notice), ad spend vs our fee (never mixed in one charge), experts seeing customer data (scoped, time-limited access only, logged).

Module D · Business email

Why: businesses get name@theirshop.com from their hosting company. On Grid Commerce there is no separate host, so email must come from us, sold per mailbox. It is also a retention lock: a shop's email living on Grid Commerce makes leaving harder.
Decision for the partners and Bablu vai (not for this front end): run our own mail servers, or resell a provider (Zoho Mail, Google Workspace, Titan, or a self-hosted Mailcow). Reselling is far less risk (spam blacklists, deliverability, uptime, storage). Build the front end provider-neutral so either works.

D1 · Merchant side (Settings › Email, or its own menu item under Settings)

  1. Setup wizard: needs a connected custom domain (link to Settings › Domains if none) → pick a plan → verify the domain (TXT) → DNS records to add (MX, SPF, DKIM, DMARC) with copy buttons and a live status per record (demo: turns green after a moment); if the domain is managed by Grid Commerce, "Add records for me".
  2. Mailboxes: create (name, address, password or invite link, storage), reset password, require two-step sign-in, change storage, suspend, delete with a confirm and a 30-day restore. Connect to Users & roles: inviting a staff member can create their mailbox; HR offboarding suspends it and forwards mail to the manager.
  3. Addresses: aliases (info@ → owner), group addresses (sales@ → 3 people), forwarders (internal/external), catch-all, auto-reply/out-of-office.
  4. Use it: "Open webmail" (opens the provider's webmail; demo page), phone/desktop setup (IMAP/SMTP/POP settings to copy, a QR code for phones), import old mail from the previous host (IMAP import wizard, demo progress).
  5. Plan & usage: mailboxes used/available, storage per mailbox, buy more mailboxes or storage (billed like other add-ons; monthly or yearly), sending limits, a simple spam/quarantine view.
  6. Shop emails: order and notification emails are sent from the shop's own domain once DKIM/SPF are green (ties into Order notifications).

D2 · Super admin side

  • Mail plans and prices (per mailbox, storage tiers, included mailboxes per edition/plan, yearly discount); provider settings page (placeholder for the backend).
  • Directory: all mail domains and mailboxes by store with DNS health, storage use and last sign-in; filters for problems.
  • Abuse and limits: sending caps, spam complaints, suspend a mailbox or a domain with reason (logged, merchant notified).
  • Money: email revenue vs provider cost per seat; usage alerts (near quota, failed DNS for 3+ days).

Done when: a merchant connects a domain, sees all four DNS records go green (demo), creates 3 mailboxes, a sales@ group and an info@ alias, buys 10 GB more, sets up the phone app with the QR, and an HR offboarding suspends a mailbox; super admin sees the domain, usage, revenue and can suspend for abuse.
